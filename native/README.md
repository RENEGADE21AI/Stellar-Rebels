# Stellar Rebels mobile validation

`native/` is the Expo source for `@renegade21ai/stellar-rebels`. Its WebView boots from packaged game files, including offline on first launch. The shell handles safe-area insets, foreground music, app interruptions, haptics, and a pilot profile in AsyncStorage outside the flight cache. The browser keeps its own IndexedDB profile. Android backups and transfers depend on device settings. [Android Auto Backup](https://developer.android.com/identity/data/autobackup)

Act I's five main missions and three optional operations, the three earnable ships, both Specials, Practice and the opening upgrade tiers are free. A permanent Full Game Unlock opens the remainder of the campaign and the ending, followed by Veteran and Endless after Standard completion. The native host authorizes launches through RevenueCat. It displays the localized product price and supports restoring through **Settings → Full Game Unlock → Restore Purchases**. Purchases use a guest RevenueCat identity and the device's store account. The browser remains free and has a separate pilot profile.

## Reproduce the source package

1. Check out the approved mobile source revision in a clean working tree. Clear `STELLAR_ENABLE_GOOGLE_SIGN_IN` and run `node scripts/build_stellar.js` from the repository root with Node 22. Check `dist-stellar/version.json` for the reviewed commit, pack fingerprint and `googleSignIn: false`. Keep the separate, Google-enabled public Hosting build out of this step.
2. In `native/`, run `npm ci`, `npm run prepare:flight`, and `npx expo config --type introspect`. The staging script creates the exact game pack, metadata, a local HTML proof, and platform graphics under `native/generated/`. It rejects dirty web artifacts and caps the ZIP at 12 MiB.
3. With the root Playwright dependencies installed, run `node native/scripts/verify-flight.cjs` from the repository root. It checks every ZIP entry against the local proof, opens the packaged file in Chromium and WebKit with HTTP requests blocked, and checks story, flight, persistence and interruption through a mock music and storage host. Use an installed build to measure actual audio and OS behavior.
4. Preserve `flight.zip`, `version.json`, `icon.png`, `launch.png`, `adaptive.png`, `loading.jpg`, and `loading-wordmark.png` under `native/generated/`. The root `.easignore` limits the EAS upload to the Expo application, lockfile, native entry and those seven outputs. The standalone app and its `eas.json` live under `native/`. [Expo asset bundling](https://docs.expo.dev/develop/user-interface/assets/) · [Expo Build in a monorepo](https://docs.expo.dev/build-reference/build-with-monorepos/) · [EAS archive rules](https://docs.expo.dev/build-reference/easignore/)

Keep EAS `requireCommit` disabled so `.easignore` can include the locally generated flight files. Check the source checkout is clean separately. Before queueing production, run `eas build:inspect --platform android --profile production --stage archive --output <fresh-path>` inside `native/`, and verify the archive includes all seven generated files with the staged hashes. The iOS profile uses the same upload rules.

## Approval and device scope

Use `validation` for the direct Android APK and `production` for the Google Play AAB or the iOS archive for internal TestFlight. Both use `com.renegade21ai.stellarrebels`. Set `EXPO_PUBLIC_REVENUECAT_IOS_API_KEY` and `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY` to the corresponding public platform SDK keys in EAS. Configure the non-consumable `stellar_rebels_full_arcade` under the current offering and map it to `full_arcade`. Without a matching SDK key and product the free game opens and the purchase screen shows store availability. Use `internal-test-store` only on Android with `EXPO_PUBLIC_REVENUECAT_TEST_API_KEY` in the preview environment. Its debuggable `.teststore` package is separate from standard builds. Check quotas, archive hashes, and signing before queueing. [RevenueCat Test Store](https://www.revenuecat.com/docs/test-and-launch/sandbox/test-store) · [Expo SDK versions](https://docs.expo.dev/versions/latest/) · [Apple SDK submission requirements](https://developer.apple.com/news/upcoming-requirements/?id=04282026a) · [Google Play API requirements](https://developer.android.com/google/play/requirements/target-sdk)

Help & Legal is available from the title screen and Settings. It includes offline privacy, terms and support pages and the manual rating link. Enable the appropriate `EXPO_PUBLIC_STELLAR_IOS_STORE_LIVE=1` or `EXPO_PUBLIC_STELLAR_ANDROID_STORE_LIVE=1` only when that platform’s public listing is reachable. The rating action opens the official store. The first durable Mission 5 clear offers a secondary preview of the full campaign after rewards settle. Selecting a paid row or opening Full Game Unlock from Settings also reaches the offer. [Apple review links](https://developer.apple.com/documentation/StoreKit/requesting-app-store-reviews) · [Google Play review guidance](https://developer.android.com/guide/playcore/in-app-review)

On a compact physical phone and a recent tall phone on both platforms, verify airplane-mode cold launch, first start, touch drag and reanchor, two-finger Hop, safe areas, and save across process kill and app update. Confirm Home and Lock pause flight and music, the game does not appear in lock-screen audio controls, and resuming a flight requires the pilot's input. Measure sustained frame timing and memory during Wraith, Flagship and Endless. Validate iPad and foldable layouts where offered. Verify native library alignment in the Android output and run it on a 16 KB environment. [Apple multitasking and resizing](https://developer.apple.com/documentation/technotes/tn3192-Migrating-your-app-from-the-deprecated-UIRequiresFullScreen-key) · [Android game resizability](https://developer.android.com/games/develop/multiplatform/support-large-screen-resizability) · [Android 16 KB support](https://developer.android.com/guide/practices/page-sizes)

Before public submission, inspect the signed artifacts and permissions, confirm publisher contact, provide an in-app and public privacy policy, complete store privacy/Data Safety and age/content declarations, and capture the installed game for listing assets. Inspect Apple's generated privacy report against the included dependency manifests and validate RevenueCat purchase history disclosures. Verify purchase, cancellation, pending orders, restore, reinstall, offline access and revocation in both store sandboxes. [Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/) · [Apple privacy details](https://developer.apple.com/app-store/app-privacy-details/) · [Google Play User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311)
